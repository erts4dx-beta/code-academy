=== 입문 | intro | 데이터베이스와 SQL 소개
**관계형 데이터베이스(RDBMS)** 는 데이터를 **테이블(표)** 로 저장합니다. 테이블은 **행(row, 레코드)** 과 **열(column, 필드)** 로 구성되며, 테이블끼리 키로 연결(관계)됩니다. 대표적인 제품으로 PostgreSQL, MySQL, Oracle, SQL Server, SQLite가 있습니다.

**SQL(Structured Query Language)** 은 이런 데이터베이스와 대화하는 선언형 언어입니다. "어떻게"가 아니라 **"무엇을"** 원하는지 기술하면 DB가 최적의 실행 방법을 찾아 줍니다.

## SQL 명령의 분류
- **DDL**(정의): `CREATE`, `ALTER`, `DROP` — 테이블 구조
- **DML**(조작): `SELECT`, `INSERT`, `UPDATE`, `DELETE` — 데이터
- **DCL**(권한): `GRANT`, `REVOKE`
- **TCL**(트랜잭션): `COMMIT`, `ROLLBACK`

## 실습 환경
가장 쉬운 방법은 **SQLite**(설치가 거의 필요 없는 파일 기반 DB)입니다. `sqlite3 test.db` 로 실행하거나, DB Browser for SQLite, DBeaver 같은 GUI 도구, 또는 온라인 SQL 실습 사이트를 이용하세요.

> SQL 키워드는 대소문자를 구분하지 않지만, **키워드는 대문자**, 테이블/열 이름은 소문자로 쓰는 것이 관례입니다. 문장 끝에는 세미콜론을 붙입니다.

=== 입문 | select | SELECT 기초: WHERE, ORDER BY, LIMIT
## 기본 구조
```sql
SELECT 열1, 열2 FROM 테이블 WHERE 조건 ORDER BY 열 LIMIT 개수;
```

## WHERE 조건
- 비교: `=`, `<>` 또는 `!=`, `<`, `>`, `<=`, `>=`
- 논리: `AND`, `OR`, `NOT`
- 범위: `BETWEEN 10 AND 20` (양 끝 포함)
- 목록: `IN ('서울', '부산')`
- 패턴: `LIKE '김%'` (`%` 는 0개 이상의 문자, `_` 는 정확히 1문자)
- NULL 검사: `IS NULL`, `IS NOT NULL` (**`= NULL` 은 항상 동작하지 않음**)

## 정렬과 제한
- `ORDER BY price DESC, name ASC` — 기본은 오름차순(ASC)
- `LIMIT 5 OFFSET 10` — 페이지네이션 (Oracle/SQL Server는 `FETCH FIRST` 문법)
- `DISTINCT` — 중복 제거
- `AS` — 열 별칭
--- code

INSERT INTO products (name, category, price, stock) VALUES
    ('무선 마우스', '전자', 25000, 120),

=== 입문 | modify | INSERT, UPDATE, DELETE와 제약 조건
## 데이터 변경
- `INSERT INTO 테이블 (열...) VALUES (...), (...);` — 여러 행을 한 번에
- `UPDATE 테이블 SET 열 = 값 WHERE 조건;`
- `DELETE FROM 테이블 WHERE 조건;`

> **WHERE 없는 UPDATE/DELETE는 테이블 전체를 바꿉니다!** 실행 전에 같은 조건으로 `SELECT` 해서 대상을 먼저 확인하는 습관을 들이세요.

## 제약 조건(Constraints)
데이터의 무결성을 DB가 보장하게 합니다.
- `PRIMARY KEY`: 각 행의 고유 식별자 (NULL 불가, 중복 불가)
- `NOT NULL`, `UNIQUE`, `DEFAULT 값`
- `CHECK (price >= 0)`: 조건 검사
- `FOREIGN KEY ... REFERENCES`: 다른 테이블의 키를 참조 (다음 레슨)

## 자동 증가 키
SQLite `INTEGER PRIMARY KEY`, PostgreSQL `GENERATED ALWAYS AS IDENTITY`(또는 `SERIAL`), MySQL `AUTO_INCREMENT`.
--- code
CREATE TABLE members (
    id         INTEGER PRIMARY KEY,
    email      TEXT NOT NULL UNIQUE,
    name       TEXT NOT NULL,
    point      INTEGER NOT NULL DEFAULT 0 CHECK (point >= 0),
    created_at TEXT DEFAULT CURRENT_TIMESTAMP
);

INSERT INTO members (email, name) VALUES ('kim@example.com', '김철수');
INSERT INTO members (email, name, point) VALUES
    ('lee@example.com', '이영희', 500),
    ('park@example.com', '박민수', 1200);

-- 확인 후 수정
SELECT * FROM members WHERE email = 'kim@example.com';
UPDATE members SET point = point + 100 WHERE email = 'kim@example.com';

UPDATE members SET point = point * 2 WHERE point >= 1000;

DELETE FROM members WHERE name = '이영희';

SELECT id, email, name, point FROM members;

=== 초급 | aggregate | 집계 함수와 GROUP BY
## 집계 함수
여러 행을 하나의 값으로 요약합니다.
- `COUNT(*)`: 행 수, `COUNT(열)`: NULL이 아닌 값의 수
- `SUM`, `AVG`, `MIN`, `MAX`
- 집계 함수는 NULL을 무시합니다.

## GROUP BY
특정 열의 값이 같은 행끼리 묶어 그룹별로 집계합니다. SELECT 절에는 **GROUP BY에 쓴 열과 집계 함수만** 올 수 있습니다(표준 SQL).

## HAVING
그룹에 조건을 겁니다. **WHERE는 그룹화 전 개별 행**을, **HAVING은 그룹화 후 결과**를 걸러 냅니다.

## 실행 순서
`FROM` → `WHERE` → `GROUP BY` → `HAVING` → `SELECT` → `ORDER BY` → `LIMIT`. 그래서 WHERE에서는 SELECT의 별칭을 쓸 수 없습니다.
--- code
CREATE TABLE orders (id INTEGER PRIMARY KEY, customer TEXT, product TEXT, category TEXT, amount INTEGER, order_date TEXT);
INSERT INTO orders (customer, product, category, amount, order_date) VALUES
    ('김철수', '노트북', '전자', 1500000, '2026-09-01'),
    ('이영희', '마우스', '전자', 30000, '2026-09-02'),
    ('김철수', '책상', '가구', 250000, '2026-09-05'),
    ('박민수', '키보드', '전자', 90000, '2026-09-07'),
    ('이영희', '의자', '가구', 180000, '2026-09-10'),
    ('김철수', '마우스', '전자', 30000, '2026-09-15'),
    ('최지우', '노트', '문구', 3000, '2026-09-20');

SELECT COUNT(*) AS 주문수, SUM(amount) AS 총매출, AVG(amount) AS 평균, MAX(amount) AS 최대
FROM orders;

SELECT category, COUNT(*) AS cnt, SUM(amount) AS total
FROM orders
GROUP BY category
ORDER BY total DESC;

-- 주문을 2번 이상 한 고객과 총 구매액
SELECT customer, COUNT(*) AS cnt, SUM(amount) AS total
FROM orders
WHERE amount >= 10000          -- 1) 소액 주문은 먼저 제외 (행 단위)
GROUP BY customer
HAVING COUNT(*) >= 2           -- 2) 그룹 단위 조건
ORDER BY total DESC;

=== 초급 | join | JOIN으로 테이블 연결하기
정규화된 데이터베이스는 정보를 여러 테이블에 나눠 저장하고 **외래 키(FOREIGN KEY)** 로 연결합니다. 흩어진 데이터를 다시 합치는 것이 **JOIN** 입니다.

## JOIN 종류
- **INNER JOIN**: 양쪽 테이블 모두에 일치하는 행만
- **LEFT (OUTER) JOIN**: 왼쪽 테이블의 모든 행 + 오른쪽에서 일치하는 행 (없으면 NULL)
- **RIGHT JOIN**: 반대 (LEFT로 테이블 순서를 바꿔 쓰는 경우가 많음)
- **FULL OUTER JOIN**: 양쪽 모두 (MySQL은 미지원, SQLite는 3.39+ 지원)
- **CROSS JOIN**: 모든 조합(카티션 곱)
- **SELF JOIN**: 같은 테이블끼리 (예: 직원-상사)

## 팁
- 테이블 별칭: `FROM orders o JOIN customers c ON o.customer_id = c.id`
- "주문하지 않은 고객 찾기" = `LEFT JOIN` + `WHERE 오른쪽.id IS NULL` (안티 조인 패턴)
--- code
CREATE TABLE customers (id INTEGER PRIMARY KEY, name TEXT, city TEXT);
CREATE TABLE orders (
    id INTEGER PRIMARY KEY,
    customer_id INTEGER REFERENCES customers(id),
    product TEXT,
    amount INTEGER
);
INSERT INTO customers VALUES (1, '김철수', '서울'), (2, '이영희', '부산'), (3, '박민수', '서울'), (4, '최지우', '대구');
INSERT INTO orders (customer_id, product, amount) VALUES
    (1, '노트북', 1500000), (1, '마우스', 30000), (2, '의자', 180000), (3, '키보드', 90000);

-- INNER JOIN: 주문이 있는 고객만
SELECT c.name, o.product, o.amount
FROM orders o
JOIN customers c ON o.customer_id = c.id
ORDER BY c.name;

-- LEFT JOIN: 모든 고객과 주문 합계 (주문 없으면 0)
SELECT c.name, COUNT(o.id) AS order_cnt, COALESCE(SUM(o.amount), 0) AS total
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
GROUP BY c.id, c.name
ORDER BY total DESC;

-- 안티 조인: 주문한 적 없는 고객
SELECT c.name
FROM customers c
LEFT JOIN orders o ON o.customer_id = c.id
WHERE o.id IS NULL;

-- SELF JOIN: 같은 도시에 사는 고객 쌍
SELECT a.name, b.name, a.city
FROM customers a
JOIN customers b ON a.city = b.city AND a.id < b.id;

=== 초급 | subquery | 서브쿼리와 CASE
## 서브쿼리
쿼리 안의 쿼리입니다.
- WHERE 절: `WHERE price > (SELECT AVG(price) FROM products)` — 단일 값
- `IN (SELECT ...)`, `EXISTS (SELECT ...)` — 존재 여부
- FROM 절의 서브쿼리(파생 테이블): `FROM (SELECT ...) AS t`
- **상관 서브쿼리**: 바깥 쿼리의 값을 참조 (행마다 실행됨)

## CASE 식
SQL의 조건 분기입니다.
```sql
CASE WHEN 조건1 THEN 값1 WHEN 조건2 THEN 값2 ELSE 기본값 END
```
SELECT에서 값을 변환하거나, 집계 함수 안에 넣어 **조건부 집계**(피벗)를 할 수 있습니다.

## 유용한 함수
`COALESCE(a, b)`(첫 번째 NULL이 아닌 값), `NULLIF`, `UPPER`/`LOWER`, `LENGTH`, `SUBSTR`, `ROUND`, 날짜 함수(DB마다 다름: SQLite `date()`, PostgreSQL `NOW()`/`DATE_TRUNC`, MySQL `NOW()`/`DATE_FORMAT`)

=== 중급 | design | 테이블 설계와 정규화
## 좋은 스키마의 원칙
- 각 테이블은 **하나의 주제**(고객, 주문, 상품)를 표현
- 모든 테이블에 **기본 키**
- 같은 정보를 여러 곳에 중복 저장하지 않기 → 수정 시 불일치(이상 현상) 방지

## 정규화 단계 (핵심만)
- **1NF**: 한 칸에 하나의 값 (예: "태그1,태그2" 처럼 쉼표로 여러 값 저장 금지)
- **2NF**: 복합 키의 일부에만 의존하는 열 분리
- **3NF**: 키가 아닌 열에 의존하는 열 분리 (예: 주문 테이블에 고객 주소를 넣지 않고 고객 테이블로)

## 관계 유형
- **1:N**: 고객 1명 — 주문 여러 개 → 주문 테이블에 `customer_id` 외래 키
- **N:M**: 학생 — 강의 → **연결 테이블**(`enrollments(student_id, course_id)`)
- 1:1: 사용자 — 프로필

> 실무에서는 성능을 위해 의도적으로 중복을 허용하는 **반정규화**를 하기도 하지만, 먼저 정규화된 설계에서 출발하세요.

=== 중급 | window | 윈도 함수
**윈도 함수**는 GROUP BY처럼 행을 합치지 않으면서, 각 행 옆에 **그룹 내 순위, 누적 합, 이전 행 값** 등을 계산합니다. 데이터 분석에서 가장 강력한 도구 중 하나입니다.

## 문법
`함수() OVER (PARTITION BY 그룹열 ORDER BY 정렬열)`
- `PARTITION BY`: 그룹 나누기 (생략하면 전체가 하나의 그룹)
- `ORDER BY`: 그룹 내 순서

## 주요 함수
- 순위: `ROW_NUMBER()`(1,2,3,4), `RANK()`(1,2,2,4), `DENSE_RANK()`(1,2,2,3)
- 집계: `SUM() OVER (...)` 누적 합, `AVG() OVER (...)` 이동 평균
- 오프셋: `LAG(열, n)` 이전 행, `LEAD(열, n)` 다음 행 → 전월 대비 증감
- `FIRST_VALUE`, `NTILE(4)`(사분위)

## CTE (WITH 절)
`WITH 이름 AS (SELECT ...)` 로 임시 결과에 이름을 붙여 복잡한 쿼리를 단계별로 읽기 쉽게 만듭니다. "그룹별 상위 N개" 문제는 CTE + `ROW_NUMBER()` 가 정석입니다.
--- code
CREATE TABLE monthly_sales (month TEXT, region TEXT, revenue INTEGER);
INSERT INTO monthly_sales VALUES
    ('2026-07', '서울', 1200), ('2026-07', '부산', 800),
    ('2026-08', '서울', 1500), ('2026-08', '부산', 750),
    ('2026-09', '서울', 1300), ('2026-09', '부산', 950);

-- 지역별 월 매출 순위와 누적 합
SELECT month, region, revenue,
       RANK() OVER (PARTITION BY month ORDER BY revenue DESC) AS rank_in_month,
       SUM(revenue) OVER (PARTITION BY region ORDER BY month) AS running_total
FROM monthly_sales
ORDER BY region, month;

-- 전월 대비 증감
SELECT region, month, revenue,
       revenue - LAG(revenue) OVER (PARTITION BY region ORDER BY month) AS diff
FROM monthly_sales
ORDER BY region, month;

-- 지역별 최고 매출 월 (그룹별 상위 1개) - CTE 사용
WITH ranked AS (
    SELECT *, ROW_NUMBER() OVER (PARTITION BY region ORDER BY revenue DESC) AS rn
    FROM monthly_sales
)
SELECT region, month, revenue FROM ranked WHERE rn = 1;

-- 순위 함수 비교
WITH scores(name, score) AS (VALUES ('A', 90), ('B', 85), ('C', 85), ('D', 70))
SELECT name, score,
       ROW_NUMBER() OVER (ORDER BY score DESC) AS row_num,
       RANK()       OVER (ORDER BY score DESC) AS rnk,
       DENSE_RANK() OVER (ORDER BY score DESC) AS dense
FROM scores;

=== 고급 | index-tx | 인덱스, 실행 계획, 트랜잭션
## 인덱스
책의 색인처럼 특정 열로 빠르게 행을 찾게 해 주는 자료구조(주로 B-트리)입니다.
- `CREATE INDEX idx_orders_customer ON orders(customer_id);`
- WHERE, JOIN, ORDER BY에 자주 쓰이는 열에 만듭니다.
- **복합 인덱스** `(a, b)` 는 `a` 조건 또는 `a AND b` 조건에 사용되지만 `b` 단독 조건에는 보통 쓰이지 않습니다(왼쪽 접두사 규칙).
- 단점: 쓰기(INSERT/UPDATE) 속도 저하, 저장 공간 증가 → 무분별하게 만들지 않기
- 열에 함수를 씌우면(`WHERE UPPER(email) = ...`) 일반 인덱스를 못 탈 수 있습니다.

## 실행 계획
`EXPLAIN QUERY PLAN`(SQLite), `EXPLAIN ANALYZE`(PostgreSQL), `EXPLAIN`(MySQL)로 DB가 쿼리를 어떻게 실행하는지 확인합니다. "SCAN"(전체 탐색)이 "SEARCH ... USING INDEX"로 바뀌는지 보세요.

## 트랜잭션과 ACID
여러 SQL을 **하나의 작업 단위**로 묶습니다. 모두 성공하면 `COMMIT`, 하나라도 실패하면 `ROLLBACK` 으로 전부 취소합니다. (계좌 이체에서 출금만 되고 입금이 안 되는 상황을 방지)
- **A**tomicity(원자성), **C**onsistency(일관성), **I**solation(격리성), **D**urability(지속성)
--- code
CREATE TABLE accounts (id INTEGER PRIMARY KEY, owner TEXT, balance INTEGER NOT NULL CHECK (balance >= 0));
INSERT INTO accounts VALUES (1, '김철수', 100000), (2, '이영희', 50000);

-- 트랜잭션: 계좌 이체 (둘 다 성공해야 의미 있음)
BEGIN TRANSACTION;
UPDATE accounts SET balance = balance - 30000 WHERE id = 1;
UPDATE accounts SET balance = balance + 30000 WHERE id = 2;
COMMIT;
SELECT * FROM accounts;

-- 실수했을 때 되돌리기
BEGIN;
UPDATE accounts SET balance = 0;      -- 앗, WHERE를 빼먹었다!
ROLLBACK;                              -- 전부 취소
SELECT * FROM accounts;               -- 원래 값 유지

-- 인덱스와 실행 계획
CREATE TABLE logs (id INTEGER PRIMARY KEY, user_id INTEGER, action TEXT, created_at TEXT);
WITH RECURSIVE n(x) AS (SELECT 1 UNION ALL SELECT x + 1 FROM n WHERE x < 10000)
INSERT INTO logs (user_id, action, created_at)
SELECT x % 500, CASE WHEN x % 3 = 0 THEN 'login' ELSE 'view' END, date('2026-01-01', '+' || (x % 270) || ' days')
FROM n;

EXPLAIN QUERY PLAN SELECT * FROM logs WHERE user_id = 42;       -- SCAN logs
CREATE INDEX idx_logs_user_date ON logs(user_id, created_at);
EXPLAIN QUERY PLAN SELECT * FROM logs WHERE user_id = 42;       -- SEARCH ... USING INDEX
SELECT COUNT(*) FROM logs WHERE user_id = 42 AND created_at >= '2026-06-01';

! 복합 인덱스는 왼쪽 열부터 사용됩니다(왼쪽 접두사 규칙).
? 트랜잭션의 원자성(Atomicity)이 의미하는 것은?
+ 트랜잭션 안의 작업은 모두 반영되거나 모두 취소된다
- 트랜잭션은 매우 빠르게 실행된다
- 한 번에 하나의 사용자만 접속할 수 있다
- 데이터가 암호화된다
! 이체 중 오류가 나면 출금과 입금이 함께 취소되어야 합니다.

=== 고급 | advanced | 고급 쿼리: 재귀 CTE, 뷰, UPSERT
## 재귀 CTE
`WITH RECURSIVE` 로 자기 자신을 참조하는 쿼리를 작성해 **계층 구조**(조직도, 카테고리 트리, 댓글 스레드)나 연속 데이터(날짜 시리즈)를 다룹니다. 기본 부분(anchor) + `UNION ALL` + 재귀 부분으로 구성됩니다.

## 뷰(VIEW)
자주 쓰는 복잡한 쿼리에 이름을 붙여 **가상 테이블**처럼 사용합니다. 권한 관리(민감한 열 숨기기)에도 유용합니다.

## UPSERT
"있으면 수정, 없으면 삽입". SQLite/PostgreSQL은 `INSERT ... ON CONFLICT (키) DO UPDATE SET ...`, MySQL은 `ON DUPLICATE KEY UPDATE`.

## SQL 인젝션 주의
애플리케이션에서 SQL을 만들 때 사용자 입력을 문자열로 이어 붙이면 안 됩니다. 항상 **매개변수 바인딩**(prepared statement)을 사용하세요. 예: Python `cur.execute("SELECT * FROM users WHERE id = ?", (user_id,))`
--- code
CREATE TABLE employees (id INTEGER PRIMARY KEY, name TEXT, manager_id INTEGER REFERENCES employees(id));
INSERT INTO employees VALUES
    (1, '대표', NULL), (2, 'CTO', 1), (3, 'CFO', 1),
    (4, '개발팀장', 2), (5, '개발자A', 4), (6, '개발자B', 4), (7, '회계담당', 3);

-- 재귀 CTE: 조직도 (깊이와 경로 포함)
WITH RECURSIVE org(id, name, depth, path) AS (
    SELECT id, name, 0, name FROM employees WHERE manager_id IS NULL
    UNION ALL
    SELECT e.id, e.name, o.depth + 1, o.path || ' > ' || e.name
    FROM employees e JOIN org o ON e.manager_id = o.id
)
SELECT substr('            ', 1, depth * 2) || name AS tree, path FROM org ORDER BY path;

-- 날짜 시리즈 생성
WITH RECURSIVE days(d) AS (
    SELECT date('2026-10-01')
    UNION ALL
    SELECT date(d, '+1 day') FROM days WHERE d < '2026-10-07'
)
SELECT d, strftime('%w', d) AS weekday FROM days;

-- 뷰
CREATE VIEW team_size AS
SELECT m.name AS manager, COUNT(e.id) AS direct_reports
FROM employees m LEFT JOIN employees e ON e.manager_id = m.id
GROUP BY m.id;
SELECT * FROM team_size WHERE direct_reports > 0;

-- UPSERT: 일별 방문 수 집계
CREATE TABLE daily_visits (day TEXT PRIMARY KEY, cnt INTEGER NOT NULL);
INSERT INTO daily_visits VALUES ('2026-10-05', 1)
    ON CONFLICT(day) DO UPDATE SET cnt = cnt + 1;
INSERT INTO daily_visits VALUES ('2026-10-05', 1)
    ON CONFLICT(day) DO UPDATE SET cnt = cnt + 1;
SELECT * FROM daily_visits;     -- 2026-10-05 | 2
--- exercise
`categories(id, name, parent_id)` 테이블에 "전자제품 > 컴퓨터 > 노트북", "전자제품 > 컴퓨터 > 데스크톱", "전자제품 > 휴대폰" 구조를 넣고, 재귀 CTE로 '컴퓨터'(id로 지정)의 모든 하위 카테고리를 찾으세요.
--- solution
CREATE TABLE categories (id INTEGER PRIMARY KEY, name TEXT, parent_id INTEGER);
INSERT INTO categories VALUES
    (1, '전자제품', NULL), (2, '컴퓨터', 1), (3, '노트북', 2),
    (4, '데스크톱', 2), (5, '휴대폰', 1), (6, '게이밍 노트북', 3);

WITH RECURSIVE sub(id, name, level) AS (
    SELECT id, name, 0 FROM categories WHERE id = 2
    UNION ALL
    SELECT c.id, c.name, s.level + 1
    FROM categories c JOIN sub s ON c.parent_id = s.id
)
SELECT name, level FROM sub WHERE level > 0;
-- 노트북 1, 데스크톱 1, 게이밍 노트북 2
